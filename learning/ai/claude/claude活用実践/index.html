Claude 活用実践 — AI Fluency + 業務活用

参照コース: https://anthropic.skilljar.com/claude-101 / https://anthropic.skilljar.com/ai-fluency-framework-foundations
対象読者: Claudeの基本的な対話から一歩進み、協働の質を高めたい人。

1. AI Fluency フレームワーク

Anthropic が定義する「AI と効果的に協働できる状態」：

AI Fluency の4軸
┌─────────────────────────────────────────────┐
│  Effective  │ 意図した成果を出せる            │
│  Efficient  │ 最小の労力で最大の成果          │
│  Ethical    │ 倫理的・安全な使い方            │
│  Empowering │ 自分と周囲の能力を高める         │
└─────────────────────────────────────────────┘

インフラエンジニアとして意識すること：

  • AIが生成したコード・設定をブラインドで使わない（セキュリティリスク）
  • AIの出力を検証できるだけの基礎知識を持つ
  • AIが苦手なこと（最新情報、社内固有知識、実環境の状態）を理解する

用途 有効度 例

注意が必要な場面

状況 リスク 対策
セキュリティ設定の生成 脆弱な設定を生成することがある AWS ドキュメントで確認
最新の API / サービス情報 学習データが古い場合がある 公式ドキュメント併用
社内環境・固有設定 知識がない コンテキストを十分に与える
本番への直接適用 ハルシネーションリスク 必ず plan/dry-run で確認

構造化プロンプト（XML タグ活用）

<context>
  環境: AWS ECS on Fargate
  既存構成: ALB → ECS（2タスク）→ RDS PostgreSQL
  問題: デプロイ後にタスクが頻繁に落ちる
</context>

<logs>
[ERROR] OOMKilled: container exceeded memory limit of 512MB
[INFO] Container starting...
[ERROR] OOMKilled: ...
</logs>

<task>
以下を分析してください：
1. 根本原因の特定
2. 即時対処法（タスク定義の変更）
3. 恒久対策（アプリケーションレベル）
4. 再発防止のためのメトリクス監視設定
</task>

Few-shot プロンプト（具体例を与える）

Terraform の security group ルールを以下のフォーマットで書いてください。

例1（入力）: ALBからアプリへの8080ポート
例1（出力）:
ingress {
  from_port       = 8080
  to_port         = 8080
  protocol        = "tcp"
  security_groups = [aws_security_group.alb.id]
  description     = "ALB から アプリへのHTTPトラフィック"
}

では以下を書いてください：
- アプリからRDSへの5432ポート
- アプリからElastiCacheへの6379ポート

コード生成の品質を上げる

以下の要件で Terraform コードを生成してください。

【要件】
- リソース: ECS Fargate サービス
- 環境変数: Secrets Manager から取得
- オートスケーリング: CPU 70% でスケールアウト（最小2、最大10）

【制約】
- セキュリティグループは最小権限で
- タグは必ず付ける（Environment, ManagedBy）
- 変数は var. で外出し

【確認してほしいこと】
- IAM ロールの権限が過剰になっていないか
- ハードコードされた値がないか

CLAUDE.md で Claude Code をカスタマイズ

# CLAUDE.md（リポジトリルートに置く）

## このリポジトリについて
インフラ管理用のTerraformコード。本番AWSアカウントを管理。

## 重要なルール
- terraform apply は絶対に実行しない（CIのみ）
- セキュリティグループの 0.0.0.0/0 は絶対に追加しない
- コスト影響が大きい変更（RDSクラス変更等）は必ずコメントで警告

## よく使うコマンド
- `terraform fmt -recursive` : フォーマット
- `terraform validate` : バリデーション
- `tflint` : 追加の静的解析
